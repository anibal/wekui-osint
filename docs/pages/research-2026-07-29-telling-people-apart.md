title:: Research — three ways to tell one person from two, and the one that was wrong
type:: research

- 668 [[person]] rows on the pilot event, **zero exact name collisions**, and one woman holding four of them. 668 rows is 222,778 pairs, so nothing here could be answered by asking about every pair. Three approaches were spiked before a line of the mechanism was written, and **the first hypothesis was falsified** — which is the whole value of having spiked it.
- **The blocking, and two rules it had to learn.** Both were defects this project had already paid for once.
  - **A one-word name is a hub.** `Adriana` reads alike to `Adriana Patricia Flores`, `Adriana Pérez Pérez` and `Adriana Utrer` — three different women. A bare given name carries no identity, exactly as a generic subject carries none in [[claim]].
  - **A block must be a NEIGHBOURHOOD, not a connected component.** Transitive closure chained **223 unrelated people** into one block — the same clique defect that made a 61-claim group of the duplicate finder in [[research-2026-07-29-duplicate-claims-at-scale]]. A row and its direct neighbours cannot chain.
  - Together: **68 blocks with a largest of 223 → 144 blocks with a largest of 16.** Context blocking also found **152 pairs the name rule missed**, among them `Ezio Narducci`/`Miriam Narducci` — names alone have a ceiling.
- **Approach 1 — give the model each person's own claims and places. FALSIFIED.** It merged whole families: `Cattleya Guanipa = Mathias Hernández`, five Castillos in one group. Two faults at once, and both are mine rather than the model's.
  - **Circular.** The blocking already selects on shared place and time, so inside a block that context is near-constant and discriminates nothing. It only adds pressure to merge.
  - **Backwards.** In a disaster corpus *same building, same day* means **family** — households live together, so they were buried together, reported together and searched for together. It is evidence of DIFFERENT people.
- **Approach 2 — the name-structure judgement test.** `FIRST NAME · middle · FIRST SURNAME · second surname`, the capitals identify. It fixed the sisters case that no-guidance failed twice, but it **broke its own stated rule** — merging `Cattleya Guanipa` with `Nayhara Guanipa` — and swung 43→33 merges between identical runs. A rule stated in prose is not a rule obeyed.
- **Approach 3 — the same test with the family signal read the RIGHT way round.** *"Being named together is evidence that two entries are DIFFERENT people, not evidence that they are the same. One person recorded twice usually appears in SEPARATE reports, because two different relatives each wrote in."*
- **The measurement, graded against 22 pairs whose answer we know, each prompt run twice.** Blocks were chosen to cover every gold pair, because taking the first N covered only 15 and a thin sample cannot tell two prompts apart.
  - no guidance — 17/22, 18/22 · 39 and 40 pairs merged
  - name-structure — 18/22, 20/22 · 44 and 33
  - **+ family signal — 20/22 and 20/22 · 29 and 29**
  - **STABILITY IS THE METRIC, NOT THE PEAK SCORE.** The family prompt is the only one that gave the same answer twice — same score, same two errors. The model is non-deterministic and there is no way to pick the good run in production, so a prompt that repeats itself beats one that occasionally scores higher. It also merged a quarter fewer pairs, and **both of its errors were SPLITS** — the safe direction.
- **What a fourth pass added, and what it could not measure.** Typo coverage — rush transpositions, doubled and dropped letters, predictive-keyboard substitutions, any level of schooling — plus an explicit rule ordering. It changed nothing measurable: 17/18 both runs, same single error. **The gold set contains no rush-typo pairs at all**, only phonetic and structural variants, so the typo section is unmeasured rather than disproven. It is kept and labelled as such.
- **The ordering fix failed, and that is the finding that shaped the build.** The prompt was given an explicit precedence and named `Belkys Barreto`/`Belkis Barreto` in the line itself. It split them anyway, both runs. The co-occurrence signal is strong enough that prose cannot subordinate it — so the position rule moved into code, where a pair it settles never reaches the judge.
- **The `Laurent` cluster was set aside by the operator as too hard**, and no prompt separated it: `Laurean Calderón`, `Laurent Calderón`, `Louise Calderón`, `Laurent Lucía Calderón Mata`, `Louise Helena Calderón Mata` — three near-identical first names in one family. That is the honest residue a machine should hand over rather than guess at.
- **The general lesson, and it outlives names.** Contextualization beats string distance — **but context carries a SIGN, and reading it backwards is worse than omitting it.** Work out which way a signal points before showing it to a model. See [[decision-2026-07-29-a-machine-may-fold-a-person]] and, for the mirror image, [[decision-2026-07-29-the-record-knows-who]] — ask the record before you ask a model.
